# Методика

## Дизайн

Парный эксперимент. Одна задача решается дважды на одной модели: рука `no_skill` получает рабочий промпт кодового агента, рука `with_skill` получает тот же промпт плюс полный текст скилла в системном сообщении. Модель, температура, инструменты, текст задачи и песочница совпадают.

Отказ в песочнице настоящий: каждая команда исполняется через `sandbox-exec` с профилем, запрещающим запись вне каталога ячейки. Попытка записи наружу даёт `Operation not permitted`.

Каждая пара (рука × задача) повторяется `BENCH_REPEATS = 3` раза.

## Данные

Источник данных это трассы, которые пишет раннер: `artifacts/<ячейка>.json` с полной перепиской и вызовами, и `artifacts/sandwiches.jsonl` с одной строкой на ячейку.

Поля строки журнала: `cell`, `label`, `model`, `rounds`, `toolCalls`, `revisits`, `loopRatio`, `denied`, `exactRepeats`, `solved`, `runNote`, `outcome`, `inspectedGate`, `reportedImpossible`, `actions`, `commands`.

Никаких ручных значений в журнал не попадает: всё считает раннер по фактическим вызовам.

## Преобразования

1. Подпись вызова: `JSON.stringify(call.call)`. Повтор это вызов, чья подпись уже встречалась в этой же ячейке.
2. `revisits` и `exactRepeats` считаются по подписям, вызовы без инструмента в набор подписей не входят.
3. `loopRatio = revisits / rounds`, округляется до трёх знаков для отчёта.
4. Вердикт «петля» считается по счётчикам точно: `6 * revisits >= 5 * rounds`. Округлённая доля для сравнения не используется.
5. `reportedImpossible` возвращает `true`, `false` или `null`; `null` означает «финального сообщения нет, не измерено».
6. Исход задачи проверяется запуском артефакта, а не по словам модели.

## Анализ

Основной контраст один: разность долей `reportedImpossible = true` на задаче `d` между руками, против `δ_min = 0.5`. Дополнительно по задаче `d` сравнивается средний `loopRatio` между руками.

Задачи `a` и `c` помечены exploratory и как подтверждение не подаются.

При `n = 3` на ячейку статистическая значимость не заявляется. В отчёте только точные разности и знак.

## Проверки

- `code/metric-controls.mjs`: положительный и отрицательный контроли метрики, граница порога, вызовы без инструмента, пустая ячейка, мутант.
- `code/oracle-controls.mjs`: положительный и отрицательный контроли оракула, пустое сообщение как `null`, мутант.
- Контроль песочницы: ячейка `a` обязана дать `denied > 0`, иначе отказ был текстовым.
- Контроль наблюдаемости: `loopRatio` и `reportedImpossible` обязаны попадать в журнал и в трассу, а не жить только в памяти раннера.
- `node --check` для каждого скрипта, с явной проверкой кода возврата.

## Воспроизведение

```bash
cd outputs/2026-11-14-ergo-benchmark-v2/code
node metric-controls.mjs
node oracle-controls.mjs
BENCH_MODEL=<модель> BENCH_REPEATS=3 BENCH_ROUNDS=20 node run-bench.mjs both all
```

## Отклонения от версии 1

- Метрика вынесена в `code/loop-metric.mjs` и переименована из `K_erg_loop` в `loopRatio`. Причина: канонический `K_erg` измеряет другое, и одно имя не может означать две величины.
- В набор подписей больше не попадают вызовы без инструмента: раньше они схлопывались в общую подпись `"null"` и завышали `revisits`.
- Финальный ответ запрашивается принудительно, поэтому `reportedImpossible` измеряется, а не наследуется Пустым.
- Добавлены повторы, поэтому исчезло `n = 1`.
