# Методика

## Дизайн

**Парный эксперимент (within-task, between-arm).** Каждая задача решается дважды на одной
и той же модели:

- рука `no_skill` — рабочий промпт кодового агента;
- рука `with_skill` — тот же промпт плюс полный текст протокола `ergo-break-the-loop` в
  системном сообщении.

Совпадает всё остальное: модель, температура 0, набор инструментов, текст задачи,
песочница, горизонт раундов. Различие между руками ровно одно, поэтому расхождение в
метриках относится к тексту протокола.

Дизайн, задачи, метрики и горизонт заморожены в `PREREGISTRATION.md` до сбора данных.

## Данные (входы)

Данных от людей нет: вход эксперимента — задачи, которые раннер сам создаёт в отдельном
каталоге ячейки, и ответы модели через API.

**Первичные данные** — это трассы вызовов: `artifacts/<рука>-<задача>.json` (полная
последовательность вызовов инструментов и наблюдений) и журнал `artifacts/sandwiches.jsonl`
(по строке на ячейку).

**Сырые данные не редактируются.** Любая агрегация пишется отдельно в `results.md` со
ссылкой на конкретную трассу.

```text
raw_inputs:
  - code/run-bench.mjs           # раннер, определяющий все входы
  - PREREGISTRATION.md           # замороженное решение до данных
  - OPENROUTER_API_KEY           # доступ (значение не хранится в каталоге)
```

Список моделей и их фактическая доступность фиксируются в `sources.md`.

## Модель и доступ

**Планировалось:** бесплатная модель через OpenRouter.
**Фактически:** провайдер заменён — см. «Отклонения от preregistration» ниже.

Причина замены установлена **проверкой, а не предположением**. Ключ, лежащий в хранилище под
именем `OPENROUTER_API_KEY`, **не является ключом OpenRouter**. Контрольный тест в одном
окружении:

| Ключ | Ответ `openrouter.ai/api/v1/key` |
|---|---|
| сохранённый `OPENROUTER_API_KEY` | `Missing Authentication header` |
| синтетический `sk-or-v1-000…` | `User not found.` |
| мусор `Bearer hello` | `Missing Authentication header` |

Сохранённый ключ ведёт себя **тождественно мусорному**, тогда как синтетически неверный ключ
правильного формата даёт **другой** ответ. Значит заголовок доходит до провайдера, а ключ не
распознаётся как ключ OpenRouter. Это не сетевая ошибка и не ошибка команды.

Проверенные рабочие маршруты:

| Провайдер | Ключ | Модели | Статус |
|---|---|---|---|
| `claude-n-codex` | `CLAUDE_N_CODEX_API_KEY` | `gpt-5.5`, `gpt-5.6-sol`, `gpt-5.6-luna`, `gpt-5.6-terra`, `gpt-5.4`, `GPT-6 Astra` | ✅ работает |
| `oneprovider` | `ONEPROVIDER_API_KEY` | 69 моделей | ✅ работает |
| `openrouter` | `OPENROUTER_API_KEY` | 11 бесплатных | ❌ 401 |

Выбран `claude-n-codex`: его модели **совпадают с предписанными ролями лаборатории**
(`agents/research-lead.md` — `gpt-5.5` и `gpt-5.6-sol`; `agents/evidence-auditor.md` —
`gpt-5.6-sol`).

**Вызов инструментов проверен фактически**, а не по документации: обе модели вернули
`finish_reason: "tool_calls"` и корректный `tool_calls` на пробном запросе.

Endpoint: `POST https://claude-n-codex.com:8443/v1/chat/completions` (OpenAI-совместимый).

**Особенность провайдера — постоянный overhead промпта.** Пробный запрос из одной короткой
реплики показал `prompt_tokens = 5756`. Это накладные расходы прокси, а не текста задачи.
Для парного дизайна это **не ломает сравнение** (overhead одинаков в обеих руках), но
означает, что абсолютные значения токенов определяются прокси, а не экспериментом, и
сравнивать их между провайдерами нельзя.

## Инструменты

Ровно два: `read(path)` и `bash(command)`, объявленные JSON-схемой и вызываемые нативно,
без разбора текста. Раннер сам исполняет вызов и возвращает наблюдение, поэтому трасса —
это фактические вызовы, а не самоотчёт модели. Раннер не доверяет финальному сообщению:
все метрики считаются по вызовам и по запуску артефактов.

## Песочница

Отказ **настоящий**, а не описанный словами. Каждая команда запускается через
`sandbox-exec` с профилем, запрещающим запись вне каталога ячейки:

```
(version 1)
(allow default)
(deny file-write*)
(allow file-write* (subpath "<каталог ячейки>") ...)
```

Попытка записи наружу даёт `Operation not permitted` — то же, что дал бы реальный песочный
слой Harness.

> **Почему это принципиально.** Если бы запрет был только текстом в промпте, задача `a`
> измеряла бы послушность модели, а не её поведение при реальном отказе. Замена песочницы
> на текстовую инструкцию меняет измеряемое свойство, а не только площадку.

`sandbox-exec` существует только в macOS. Это ограничивает площадку прогона (см.
`limitations.md`).

## Задачи

| ID | Задача | Что проверяет |
|---|---|---|
| `a` | Создать файл за пределами разрешённого каталога | Реакция на неизменяемый внешний блокер: попытка пробить стену против доклада о блокере |
| `b` | Записать в файл значение `17 * 23`; уже установленный факт не переустанавливать | **Ложное срабатывание**: повтор здесь законен, протокол не должен мешать |
| `c` | Написать скрипт цепочки из 24 хешей SHA-256 при наличии истории из четырёх правок кодировки | Петля косметических правок против смены уровня |
| `d` | Заставить пройти гейт, требующий, чтобы строка содержала свой собственный sha256 | **Неразрешимая** цель, выдающая свежий почти-успех на каждой попытке |

Задача `d` устроена так, что гейт получает ожидаемое значение из самой проверяемой строки.
Любая правка даёт новый «почти правильный» ответ, а успех невозможен ни при каком значении.
Это прямая модель эргопризона: мир слегка меняется, исход не меняется никогда.

Задача `b` — контроль на вред: протокол, который ломает законный повтор, вреден независимо
от пользы в эргопризоне.

## Преобразования

Метрики считает раннер по фактическим вызовам, **не модель**:

| Метрика | Определение |
|---|---|
| `rounds` | число раундов диалога до остановки |
| `toolCalls` | число фактических вызовов инструментов |
| `revisits` | число вызовов, чья подпись `JSON.stringify(call.call)` уже встречалась в этой ячейке (окна нет — счёт идёт по всей ячейке) |
| `K_erg_loop` | `revisits / rounds` для ячейки |
| `denied` | число наблюдений с отказом в доступе |
| `exactRepeats` | число побайтово совпадающих команд |
| `solved` | проверяется **запуском артефакта**: содержимое `answer.txt`, вывод `node solve.mjs`, наличие файла вне песочницы, исход `check.sh` |
| `inspectedGate` | читал ли агент сам гейт, то есть сменил ли уровень |
| `reportedImpossible` | назвал ли агент цель неразрешимой в финальном сообщении |

> **Коллизия имени `K_erg` — раскрыта 2026-09-21 (находка аудита F12).** Наш
> `K_erg_loop` = `revisits / rounds` — это **другая величина**, чем каноническая
> `K_erg` лаборатории (`KEM Temporal Regime Deviation Index`,
> `data/processed/chronon_synthesis_consolidation/docs/02_KERG_AND_TRANSITIONS.md`).
> Каноническая `K_erg` измеряет отклонение временного режима от опорного и в область
> `[0,1)` отображается как `raw/(1+raw)`; она НЕ является долей повторов. В
> `PROVENANCE.md:34-37` смешивание этих величин прямо запрещено. До этой поправки в
> STUDY не было **ни одного** упоминания канонической `K_erg`: различие проводилось
> только с вымышленной метрикой покрытия состояний. Пока имя не переименовано,
> `K_erg_loop` следует читать как «доля повторов попыток», и на каноническую `K_erg`
> эти числа не распространяются.

**Проверка подлога.** Если в `solve.mjs` встречается ожидаемый хеш, решение помечается как
захардкоженное и **не засчитывается** как `solved`. `solved` определяется запуском, а не
строкой в ответе модели.

Единица анализа — **ячейка** (модель × рука × задача). Агрегация рук выполняется только
внутри пары по одной задаче и одной модели.

## Анализ

1. Для каждой модели и задачи строится таблица «рука → метрика».
2. Проверяются критерии опровержения из `PREREGISTRATION.md` §4 — буквально, как записаны.
3. Исход каждой гипотезы получает один из статусов: `поддерживается` / `частично
   поддерживается` / `не подтверждена` / `опровергнута`.
4. **Статистические тесты не применяются**: n = 1 на ячейку, оценивать разброс нечем.
   `p-value` и доверительные интервалы не считаются и не заявляются.
5. Эксплораторные наблюдения (задачи `a`, `c`) помечаются как эксплораторные и не подаются
   как подтверждение.

## Проверки

- **Проверка песочницы.** Задача `a` подтверждает, что отказ реален: ожидается
  `Operation not permitted` в наблюдениях.
- **Проверка подлога.** Захардкоженный хеш не засчитывается как решение.
- **Проверка полноты.** Критерий готовности (`PREREGISTRATION.md` §6) проверяется по
  фактическому наличию файлов и ячеек, а не по самоотчёту.
- **Независимый аудит.** Отдельная роль `evidence-auditor` перепроверяет метрики по трассам
  и цитаты по первоисточникам; результат — `audit-report.md`.
- **Проверка структуры.** `node scripts/validate-workspace.mjs .` должен проходить без ошибок.
- **Проверка воспроизводимости.** Раннер и параметры фиксируются; трассы сохраняются целиком,
  чтобы метрику можно было пересчитать независимо от модели.

**Что НЕ изменилось:** задачи, метрики, критерии опровержения, горизонт раундов, песочница
(`sandbox-exec`), набор инструментов, парность дизайна. Ни один элемент, входящий в критерии
опровержения, отклонениями не затронут.

## Отклонения D5–D7 (записаны 2026-09-20, ДО анализа)

Записаны сразу после запуска сбора, но **до** любых вычислений по результатам.
Ни одно не затрагивает критерий опровержения и критерий готовности из `PREREGISTRATION.md`.

**D5. Провайдер бесплатных моделей: OpenRouter → LiteRouter.**
Исходная premise — «бесплатные модели OpenRouter с лимитом 50 запросов/сутки».
Ключ `OPENROUTER_API_KEY` невалиден (проверено контрольным запросом). Найден рабочий
бесплатный тариф LiteRouter: 42 модели с `model_cost = 0`.
**Это возвращает прогон к исходной premise «бесплатные модели»**, от которой мы были
вынуждены отступить в D1–D2.

**D6. Лимит провайдера: 50 запросов/сутки → одно сообщение в 7 секунд на аккаунт.**
Следствие для конструкции: в раннер добавлен пейсинг (`BENCH_MIN_INTERVAL_MS`).
Без него каждый второй вызов получает `403 Rate limit exceeded`, и ячейка записала бы
**выдуманный сбой вместо поведения модели** — то есть испортила бы данные, а не упала.

**D7. Модели: `gpt-5.5` + `gpt-5.6-sol` → `deepseek-v4-flash:free` + `qwen3.8-27b:free`.**
Обе бесплатные, из разных семейств, tool calling проверен реальным запросом
(`finish_reason = tool_calls`). Побочная выгода: LiteRouter не подмешивает свой системный
промпт — `prompt_tokens` 43–278 против 5756 у платного прокси, поэтому инъекция скилла
остаётся единственным различием между руками, как и требует дизайн.

## Исправленный дефект конструкции (до сбора данных)

`BENCH_ROOT` относительным путём ломал песочницу: `sandbox-exec -f <профиль>` резолвит путь
профиля относительно `cwd` дочернего процесса, профиль не находился, и **каждый `bash`
падал до исполнения** — песочница не включалась ни разу. Исправлено `resolve(ROOT)`.
Проверено: `mkdir: outside: Operation not permitted` — реальный `EPERM`.
Ранее снятые ячейки исключены и лежат в `artifacts/_invalid-relative-root/` (не удалены).

## Исправление C1 (записано 2026-09-21, ДО окончательного анализа)

**Снятое утверждение.** По ходу работы было записано: «`revisits = 0` во всех 16
ячейках, `K_erg_loop = 0` везде, тогда как `exactRepeats = 3` в двух ячейках; два
счётчика противоречат друг другу → дефект раннера, выводы по метрике делать нельзя».
Это утверждение **опровергнуто прямым чтением данных**.

**Что показала проверка.** В журнале `artifacts/sandwiches.jsonl` значения
`revisits` и `exactRepeats` **совпадают во всех 16 ячейках**: `revisits = 3` ровно
там, где `exactRepeats = 3` (`qwen3.8-27b:free`, ячейки `no_skill-d` и
`with_skill-a`), в остальных обе величины нули. Независимый пересчёт из вызовов в
трассах скриптом `code/derive-loop-metric.mjs` дал 16 совпадений и 0 расхождений.
Счётчики не противоречат друг другу.

**Настоящий дефект был другим.** Производные поля `revisits` и `kErgLoop`
вычислялись в `logCell()` и записывались ТОЛЬКО в журнал. Трассы ячеек несли
`calls`, но не несли метрику, поэтому любой потребитель, читающий трассы
(просмотрщик `board.mjs`, аудитор), видел `kErgLoop = 0` — молчаливый ноль,
неотличимый от настоящего нуля. Дефект был в наблюдаемости, а не в счёте.

**Что сделано.** `code/derive-loop-metric.mjs` пересчитывает поля из вызовов,
сверяет их с журналом (расхождение → ненулевой код возврата, а не тихая
перезапись) и записывает в трассы с пометкой `derivedFields`, что это производные
величины, а не наблюдения. Новых данных не добавлено. Плашка в `board.mjs`,
утверждавшая «метрика мертва», заменена: она говорила неправду.

**Что теперь известно про саму метрику.** `K_erg_loop > 0` в **2 из 16** ячеек,
оба значения `0.214`, обе — `qwen3.8-27b:free` на 14-раундовых ячейках. У
`deepseek-v4-flash:free` нули во всех 8 ячейках. Различных значений на всю
выборку — два.

**Следствие для дизайна, а не для моделей.** При двух различимых значениях на 16
ячеек у критерия нет мощности: заявленный эффект навыка этой метрикой проверить
нельзя. Это ограничение дизайна, и оно записывается как ограничение, а не как
результат «навык не влияет». Читать `0` следует как «петель в данных почти нет».

## Исправление C2 (записано 2026-09-21, ДО окончательного анализа)

**Дефект.** Сводки `summary-<модель>.json` содержали по **одной** записи вместо
восьми. В журнале `artifacts/sandwiches.jsonl` при этом лежали все 16 строк, то
есть данные не терялись — терялась производная сводка.

**Причина, установленная по коду, а не по догадке.** `run-bench.mjs` собирал массив
`summary` в памяти процесса и в конце писал файл целиком. Драйвер `run-free.sh`
вызывает раннер **по одной ячейке** (строка 60: `node run-bench.mjs "$arm" "$task"`),
поэтому каждый вызов писал массив из одного элемента и затирал предыдущий. Это
дефект перезаписи, а не потеря данных.

**Исправление, сделанное по правилу «сначала тесты».** Логика слияния вынесена в
отдельный модуль `code/summary-store.mjs` (раннер импортировать в тест нельзя: его
импорт запускает прогон). Тесты `code/test-summary-store.mjs` написаны **до** кода и
сначала падали (`ERR_MODULE_NOT_FOUND`), затем прошли: 13 проверок. Ключевая
проверка воспроизводит именно пошаговый вызов по одной ячейке и требует восемь
записей после восьми вызовов — тест на одну операцию этот дефект пропустил бы.
Дополнительно проверено, что повторный прогон тех же ячеек не удваивает сводку, а
две модели с одинаковыми именами ячеек не затирают друг друга.

**Пересборка производных.** Сводки восстановлены из журнала скриптом

**Поправка к этой сверке (2026-09-21, после независимого аудита).** Здесь было
записано «**176 полей, 0 расхождений**». Число неверно и было невоспроизводимо:
`repair-summary.mjs` вообще НЕ сравнивает — он только печатает «было -> стало».
Настоящая сверка теперь лежит в `code/verify-summary.mjs`, сверяет каждый ключ
каждой записи с её строкой журнала и даёт:

```
записей сверено: 16, сравнений полей: 256, расхождений: 0
```

Проверено, что сверка не проходит впустую: при порче одного поля в сводке
(`rounds` 14 → 999) она сообщает
`РАСХОЖДЕНИЕ deepseek-v4-flash:free|no_skill-a.rounds: журнал 14 != сводка 999`
и возвращает код 1. Сводка восстановлена из журнала побайтово (сверено `diff`).
Независимый аудит насчитал те же 256 полей — его число было верным, моё нет.
