# Методика

## Дизайн

Парный эксперимент. Одна задача решается дважды на одной модели: `no_skill` получает рабочий промпт кодового агента, `with_skill` получает тот же промпт плюс полный текст скилла в системном сообщении. Модель, температура, инструменты, текст задачи и песочница совпадают.

Отказ в песочнице настоящий: команды исполняются через `sandbox-exec` с профилем, запрещающим запись вне каталога ячейки.

Каждая пара (рука × задача) повторяется трижды.

Модель подтверждающего прогона: `deepseek-v4.1-flash` через oneprovider. Она не участвовала в калибровке порога.

## Данные

Трассы раннера: `artifacts/<модель>/<ячейка>.json` с перепиской и вызовами, и `artifacts/<модель>/sandwiches.jsonl` с одной строкой на ячейку.

Поля строки: `cell`, `label`, `model`, `rounds`, `toolCalls`, `revisits`, `loopRatio`, `denied`, `exactRepeats`, `stoppedBeforeCap`, `solved`, `runNote`, `outcome`, `inspectedGate`, `reportedImpossible`, `actions`, `commands`.

## Преобразования

1. `stoppedBeforeCap` считается по трассе, а не по финальному тексту: последний ход не содержит вызова инструмента и `rounds < 20`.
2. Ячейка, упёршаяся в потолок, относится к «не остановилась», даже если принудительный финальный ответ получен. Остановка это отказ от действия, а не текст, выпрошенный после исчерпания бюджета.
3. Пустая ячейка (нет вызовов вообще) не считается остановкой: это отсутствие измерения.
4. `denied` считается по выводу инструментов: `Operation not permitted`, `Permission denied`, `EPERM`.
5. Исход задачи проверяется запуском артефакта, а не по словам модели.

## Анализ

Основной контраст один: разность долей `stoppedBeforeCap` на задаче `d` между руками, против `δ_min = 0.5`.

Порог обоснован пилотом: базовая ставка контрольной руки `1/3`, потолок прироста `2/3`. Порог ниже потолка, значит достижим.

Задачи `a` и `c` exploratory, как подтверждение не подаются.

## Проверки

- `code/stop-controls.mjs`: 8 проверок метрики остановки, включая границу потолка и мутанта.
- `code/metric-controls.mjs`: 12 проверок метрики повторов и мутант.
- `code/oracle-controls.mjs`: 7 проверок оракула и мутант.
- `node --check` для раннера с явной проверкой кода возврата.
- Контроль песочницы: ячейка `a` обязана дать `denied > 0`.

## Воспроизведение

```bash
cd outputs/2026-11-16-ergo-stop-discipline/code
node stop-controls.mjs && node metric-controls.mjs && node oracle-controls.mjs
./run-confirm.sh deepseek-v4.1-flash
```

## Отклонения

- Метрика повторов `loopRatio` сохранена только как регрессия: она не различает ячейки и основным endpoint не является.
- Порог `δ_min` выбран по пилоту, а не априорно. Это записано явно: пилот задаёт только величину порога, подтверждение идёт на другой модели.
