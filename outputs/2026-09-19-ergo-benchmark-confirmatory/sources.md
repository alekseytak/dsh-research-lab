# Первоисточники

Правило лаборатории: Википедия, агрегаторы и ответы моделей годятся для навигации, но не
заменяют первоисточник. Здесь перечислены **фактические** первоисточники метрики и протокола
с дословными фрагментами и указанием, что каждый фрагмент реально подтверждает.

## S1 — метрика ERGO (личные материалы Алексея по сеттингу DeCogerenc)

**Что это:** сцены и наброски глав по сеттингу DeCogerenc, входящие в базу знаний DSH.
**Происхождение:** личные материалы автора. **DOI, URL и дата издания отсутствуют.**
**Тип данных:** числовые значения — текст HUD и логов, а **не измерения**.

Дословно:

```
K_erg = fraction_of_states_visited.
ERGO–PRISON CRITERION:
K_erg > 0.9 → SUBJECT MUST EXPERIENCE ALL AVAILABLE STATES.
K_erg_joint = f(states_visited_together, harmonic_subspace).
– full traversal not required
– escape allowed if shared harmonic subspace achieved.
K_erg_joint: 0.99 → 0.8 → 0.66 → 0.4 → 0.3.
ERGODIC LOOP BROKEN
Quantum Escape Operator: ENABLED.
```

**Что подтверждает:** существование величины `K_erg` как доли посещённых состояний, порога
`0.9` и выхода через `K_erg_joint` на общем гармоническом подпространстве.

**Что НЕ подтверждает:** ничего о повторах попыток. `K_erg` считает **покрытие состояний**,
а не повторяемость действий.

**Пробелы, выявленные сверкой:**

- знаменатель доли не определён: конкурируют «all available states», «all accessible states»
  и `STORED STATES: 327`;
- определение «состояния» отсутствует;
- шкала 0..1 и вид функции `f` не заданы; у `K_erg_bundle`, `K_erg_orders` и `HONOR INDEX`
  шкалы нет вовсе;
- обоснование порога `0.9` отсутствует, знак сравнения строгий;
- **число повторов в источниках не задано нигде.**

**Метрика-обманка**, названная в том же материале:

```
K_erg_orders = fraction_of_orders_fully_executed
```

Закрытые задачи, созданные файлы и напечатанное `OK` поднимают её, пока результат остаётся
недоказанным. Для настоящей работы это прямое предупреждение: **самоотчёт агента не является
наблюдением**. Раннер бенчмарка считает метрики по фактическим вызовам именно поэтому.

Источник изложения пробелов: `library/ergo/README.md`.

## S2 — протокол `ergo-break-the-loop`

**Путь:** `~/.agents/skills/ergo-break-the-loop/SKILL.md`

Триггер срабатывания (дословно из `description`):

> Apply when the same attempt keeps failing against an unchanged world: the same action,
> target, and premise return, no new fact arrives, and more effort only produces repeats.
> Scores the window, then changes the frame instead of retrying.

Отказ переносить порог источника (дословно):

> That metric measures coverage of states, not repetition of attempts, so its 0.9 does not
> transfer. This skill keeps its own counters explicit and reuses only the frame and the escape.

**Что подтверждает:** протокол сознательно **не наследует** порог `0.9` и ведёт собственные
счётчики с явным окном.

**Следствие для дизайна:** «шесть ходов и пять повторов» — это **решение протокола** о цене
усилия, а не положение источника. Бенчмарк проверяет протокол как он есть, и не приписывает
его порогам авторитета источника.

## S3 — счётчик протокола

**Путь:** `scripts/ergo-score.mjs`, формат журнала — `library/ergo/ledger.example.jsonl`

Одна строка на ход:

```json
{"action":"run","target":"bash probe","premise":"инструмент принимает эскалацию","world":"policy=workspace-write","fact":null}
```

Вердикт считается по последним **шести** ходам: `R` не меньше пяти из шести, мир не
двигался, нового факта нет, ничего не в процессе.

**Проверено запуском** (см. `../../VERIFICATION.md`):

```
$ node scripts/ergo-score.mjs library/ergo/ledger.example.jsonl
ledger: 8 moves, window of 6
R (re-visits in window) = 0/6 (K_erg_loop 0.00)
world moved: yes | new fact in window: yes | pending: yes
```

## S4 — каталог бесплатных моделей OpenRouter

**Путь:** `https://openrouter.ai/api/v1/models` (живой запрос)

Каталог проверен при планировании пилота: **445 моделей, 19 бесплатных, 18 из них с
поддержкой `tools`**. Восемь бесплатных моделей настроены в `~/.dsh/settings.yaml`.

**Что подтверждает:** доступность бесплатных моделей с вызовом инструментов на момент
планирования. **Не подтверждает:** что конкретная модель сохранит доступность и поддержку
`tools` на момент прогона — каталог меняется, поэтому фактическая проверка фиксируется
отдельно для каждой включённой модели.

## Честные ограничения источников

- **S1 не является научной публикацией.** Это художественный материал; числа в нём —
  элементы HUD, а не результаты измерений. Поэтому метрика ERGO используется как **рамка**,
  а не как измеренная величина, и её порог не переносится.
- **Совпадение автора.** Протокол, задачи и этот бенчмарк написаны одним автором. Это
  источник смещения в пользу протокола; ограничение названо в `limitations.md` и не
  устраняется этим прогоном.
- **Самоотчёт.** Счётчики протокола заполняет сам агент, поэтому чистый счёт в его журнале —
  слабое доказательство. Бенчмарк обходит это тем, что метрики считает раннер по фактическим
  вызовам, а `solved` — запуском артефакта.
- Цитаты приведены дословно; там, где источник на английском, перевод не подставляется,
  чтобы не размывать формулировку.
