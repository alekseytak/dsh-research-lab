# Код

| Файл | Назначение |
|---|---|
| `run-bench.mjs` | раннер ячейки: системный промпт по руке, нативные вызовы инструментов, песочница, оценка |
| `loop-metric.mjs` | единственная реализация метрики повторов и точное сравнение с порогом |
| `oracle.mjs` | оракул «модель сообщила о невозможности» |
| `metric-controls.mjs` | контроли метрики и мутант, запускаются без сети |
| `oracle-controls.mjs` | контроли оракула и мутант, запускаются без сети |
| `summary-store.mjs` | слияние сводки при вызове раннера по одной ячейке |

## Почему метрика и оракул вынесены

В версии 1 обе величины жили внутри раннера и не проверялись ничем. Метрика принимала два значения на 16 ячеек, а оракул вышел константой `false`, потому что финальные сообщения были пустыми. Обе константы выглядели как измерения.

Теперь у каждой величины один модуль, один импорт и контроли, которые обязаны падать на мутанте.

## Проверка

```bash
node --check run-bench.mjs
node metric-controls.mjs
node oracle-controls.mjs
```
