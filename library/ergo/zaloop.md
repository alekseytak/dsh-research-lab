# ZaLoop: контроллер лупов

Спецификация контроллера, который следит за лупом и снижает автономию, чтобы луп не лез в залупу.

Основание: `~/документы /🔄Os глаголы и лупы .md`, разделы 1.2, 2.1, 4 и 5. Дополнено механизмом тормозов из `~/muha/03-terminal-agent/core/autonomous.py:250-285`.

Сводка места в проекте: `SPEC.md`, раздел 6.

---

## 1. Зачем

Луп, который зациклился, не должен продолжать тратить бюджет. Но и убивать сразу нельзя: чаще всего один повтор означает, что модель не видит результат, который уже получила. Поэтому реакция ступенчатая.

Три требования, из которых следует всё остальное:

1. **Ступенчатость.** Сначала подсказка, потом урезание автономии, потом теневой режим, только потом остановка.
2. **Возможность восстановления.** Задача, остановленная по бюджету, не провалена. Она возвращается в очередь.
3. **Никаких выдуманных порогов.** Каждый порог выводится из пилота на той же модели, где идёт проверка, и замораживается до прогона.

---

## 2. Место в потоке

```
шаг агента → журнал шагов → ZaLoop.supervise() → ступень → что разрешено на следующем шаге
```

Контроллер **читает** журнал и **возвращает** уровень автономии. Он не исполняет действия и не меняет задачу.

### 2.1 Что контроллер НЕ имеет права

| Запрет | Причина |
|---|---|
| обходить песочницу | отказ песочницы — сигнал, а не препятствие |
| менять цель или текст задачи | контроллер управляет автономией, а не целью |
| исполнять действия в режиме `shadow` | теневой режим это только предложения |
| использовать число как разрешение | канон: число не является ни диагнозом, ни разрешением |
| включать верхнюю границу рассеяния | не измерена, см. раздел 7 |

---

## 3. Сигналы

Считаются по журналу шагов на каждом шаге.

| Сигнал | Определение | Аналог в доках |
|---|---|---|
| `signature` | `verb\|domain\|object` для шага | Kerg / эргодичность |
| `repeatRatio` | `1 − уникальных отпечатков / шагов` | «склонность к эргодическому рассеянию» наоборот |
| `consecutiveRepeats` | сколько раз подряд последний отпечаток равен предыдущему | «1 повтор → подсказка, 3 подряд → стоп» |
| `cycle` | `{cyclic, period}` для периода 1–4 | в доках нет, добавлено по muha |
| `deniedRate` | доля шагов с отказом песочницы | `maxBlockRate` |
| `escalationRate` | доля шагов, ушедших наверх | `maxRequireHumanRate` |
| `failuresInARow` | подряд неуспешных шагов | «две ошибки подряд — шаги бессмысленны» |
| `budgetUsed` / `budgetLeft` | потрачено и остаток | `maxActionsPerHour`, `maxAutonomy` |

Сигналом является **отпечаток действия**, а не текст команды. `cat notes/a.txt` и `sed -n 1p notes/a.txt` это разный текст и одно действие. Реализация: `outputs/2026-11-17-ergo-action-signature/code/action-signature.mjs`.

## 4. Ступени

Ровно пять значений. Внутри одного лупа ступень поднимается только вверх. Сброс в `normal` происходит при **смене рамки**: если `verb` или `domain` изменился, а объект остался в том же кластере.

| Ступень | Условие | Что разрешено на следующем шаге |
|---|---|---|
| 0 `normal` | ни один порог не превышен | всё как обычно |
| 1 `nudge` | `consecutiveRepeats = 1` | всё, но в историю добавляется подсказка: результат уже получен, выбери другое действие или ответь итогом |
| 2 `reduce` | `consecutiveRepeats >= 2`, или `repeatRatio > repeatRatio_reduce` | `maxSteps` вдвое меньше, окно истории урезано до 3 |
| 3 `shadow` | `consecutiveRepeats >= 3`, или `cycle.cyclic`, или `deniedRate > deniedRate_shadow` | исполнение запрещено, только предложения; шаг не тратит бюджет инструментов |
| 4 `stop` | цикл найден после `shadow`, или `failuresInARow >= 2`, или `budgetLeft = 0` | луп остановлен, задача в очередь `PENDING`, создан `HumanReviewTicket` |

### 4.1 Почему `nudge` не остановка

Прямо из muha: один повтор — повод объяснить модели, что данные уже собраны, а не повод сдаваться. Обычно она их просто не видит.

### 4.2 Почему `failuresInARow >= 2` ведёт сразу в `stop`

Две ошибки подряд означают, что следующий шаг будет таким же бессмысленным, как предыдущий. Промежуточные ступени здесь не помогают: проблема не в автономии, а в отсутствии пути.

### 4.3 Почему цикл периода 2 ведёт в `shadow`, а не в `stop`

`A → B → A → B` это уже петля, но она может быть законной: например, чтение и проверка чередуются. Теневой режим проверяет это без траты бюджета и без убийства задачи.

## 5. Пороги

Пороги не имеют значений по умолчанию. Контроллер обязан получить файл порогов с хешем, иначе он отказывается работать.

```yaml
zaloop:
  model: glm-5.3-flash
  calibrated_on: outputs/YYYY-MM-DD-topic/artifacts/<модель>/pilot.jsonl
  repeatRatio_reduce: 0.35
  repeatRatio_shadow: 0.60
  deniedRate_shadow: 0.50
  max_steps: 20
  hash: sha256:<хеш этого файла без строки hash>
```

Требования к порогам:

1. Выведены из пилота на той же модели, на которой будет проверка.
2. Арифметически достижимы: значение ниже максимума, который пилот показал.
3. Заморожены до прогона вместе с `sha256`.
4. При попытке использовать пороги, откалиброванные на другой модели, контроллер выдаёт предупреждение с именем модели из файла.

**Пороги из документа** (`maxRequireHumanRate: 0.3`, `maxBlockRate: 0.1`, `maxAomInstabilityRate: 0.25`, `maxTemporalInstabilityEvents: 5`) — ориентиры, а не значения. Они относятся к другому субстрату.

## 6. HumanReviewTicket

Создаётся на ступени `stop`. Минимальный состав:

| Поле | Смысл |
|---|---|
| `task_id` | какая задача остановлена |
| `stop_reason` | почему: цикл, две ошибки, бюджет |
| `stage` | до какой ступени дошло |
| `steps` | журнал шагов с отпечатками |
| `signals` | значения сигналов на момент остановки |
| `repeatRatio` | итоговая доля повторов |
| `cycle` | найденный период, если был |
| `resume_from` | `PENDING`: задача не провалена, а не доведена |

Формулировка `stop_reason` пишется человеческим языком и называет наблюдение, а не оценку: «действие read filesystem /cell/notes/a.txt повторено трижды», а не «высокая эргодичность».

## 7. Двусторонность: что известно и что нет

Документы задают двустороннюю зону. Плохо не только повторение, но и рассеяние: `explorationPenaltyAbove: 0.7`, «лупы не должны бесконечно испытывать пользователя новыми стратегиями», «избегать этико-хаотических траекторий».

**Но наш замер этого не подтверждает.** Доля новизны во всех 47 пересчитанных ячейках равна `1.00`: агенты почти никогда не повторяют отпечаток дословно. Значит верхняя граница не измерена.

Поэтому:

- нижняя граница (повторение) **активна**, у неё есть рабочая шкала: задача `d`, `glm-5.3-flash`, `0.383` против `0.111`;
- верхняя граница (рассеяние) **объявлена, но неактивна**, пока не будет прогона, где она различает ячейки.

Включать неактивную границу как гейт нельзя: конъюнкт, постоянный по построению, ничего не измеряет.

## 8. Проверки контроллера

Обязательные, каждая без сети.

| Проверка | Ожидание |
|---|---|
| первый шаг | ступень `normal` |
| один повтор | `nudge`, исполнение разрешено |
| два повтора подряд | `reduce` |
| три повтора подряд | `shadow`, исполнение запрещено |
| цикл `A B A B` | `shadow`, период 2 |
| три разных отпечатка | `normal` |
| две ошибки подряд | `stop`, задача в `PENDING`, тикет создан |
| бюджет исчерпан | `stop`, тикет создан |
| смена рамки после `shadow` | возврат в `normal` |
| пороги без `hash` | отказ работать |
| пороги с чужой моделью | предупреждение с именем модели |
| **мутант**: контроллер без детектора цикла | обязан провалить проверку `A B A B` |

Последняя строка важнее остальных. Контроллер, который проходит все проверки и при этом не замечает цикл периода 2, бесполезен ровно в том случае, ради которого написан.

## 9. Что не входит

- Матрица «домен × глагол» и `is_allowed`: у нас нет глагольной грамматики.
- Феромонное поле и connectome: в muha они на выбор не влияют, переносить нечего.
- Расписание по интервалам (`schedule: interval 30m`): наши лупы это ходы внутри одной задачи, а не фоновые процессы.
- Оценка эмоциональной волатильности и AOM: нет такого сигнала.

---

## 10. Критерий готовности

Контроллер готов, когда одновременно верно:

1. Четыре ступени срабатывают каждая на своём входе, и перескоков нет.
2. Цикл периода 2 обнаруживается, мутант без детектора цикла проваливает проверку.
3. `shadow` не исполняет ни одного действия.
4. `stop` возвращает задачу в `PENDING` и создаёт тикет с человеческой причиной.
5. Пороги принимаются только с хешем, и чужая модель вызывает предупреждение.
6. Верхняя граница рассеяния присутствует в коде как объявленная, но не влияет на решение.
