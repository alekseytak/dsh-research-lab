# Отчёт аудита

## claim

Заявка, которая проверяется:

> В реализации `kerg_temporal.py` из пакета `chronon_synthesis_consolidation` были
> четыре дефекта: недостижимость объявленного типа `FIXED_POINT_HOLD`, отсутствие
> ветки `METASTABLE_TRAP`, выдача артефакта вместо измерения на замершем и почти
> замершем ряде. После правки все семь объявленных типов достижимы, а тесты
> различают подмены.

Заявка **проверена мной** и **НЕ проверена независимым аудитором**.

## вычисления

Проверки, выполненные автором правки. Это НЕ независимый аудит:

| Проверка | Команда | Исход |
|---|---|---|
| красное состояние воспроизводится | pytest на `kerg_temporal.original.py` | 4 failed, 8 passed |
| зелёное состояние | pytest на `kerg_temporal.py` | 12 passed |
| мутант M1 убит | перевёрнутая метрика | 1 failed |
| мутант M2 убит | `raw/2` | 1 failed |
| мутант M3 убит | без ε-защиты | 1 failed |
| достижимость типов | `test_every_spec_type_is_emittable` | все 7 |
| разделимость порога удержания | прямой расчёт | 0.79 против 0.26 / 0.50 / 0.15 |

Что НЕ проверено: поведение на реальных данных; корректность самого замысла
метрики; согласованность с каноном vault (там 4 несовместимых определения).

## цитаты

Дословные выдержки из источников, на которые опирается заявка.

Из `docs/02_KERG_AND_TRANSITIONS.md` (спека пакета) — объявленный список типов
включает `FIXED_POINT_HOLD` и `METASTABLE_TRAP`, то есть оба типа заявлены
каноническими.

Из оригинального `code/kerg_temporal.py`:

```python
raw = abs(v_local / (v_ref + epsilon) - 1.0)
```

— при `v_local = v_ref = 0` это даёт `raw = 1.0` и `value = 0.5`; значение
конечное, но измерением не является.

```python
def classify(...):
    ...
    return "FIXED_POINT_HOLD" if dominant_lag == 1 else "PERIODIC_LOOP"
```

— ветка `FIXED_POINT_HOLD` требует `dominant_lag == 1`, а `analyze()` вызывал
`recurrence()` без `min_lag` при дефолте `min_lag = 2`. Тип недостижим.

Из `_Аудит vault.md`:

> `Kerg`: три несовместимые формулы

Из `library/ergo/README.md` — порог `0.9` не переносится, так как означает
противоположный полюс по отношению к доле повторов попыток.

## Статус аудита

**ПРОВЕДЁН 2026-09-21, вердикт «ПОДТВЕРЖДЕНО ЧАСТИЧНО».** Независимая проверка
выполнена отдельным агентом в роли `evidence-auditor`, полный отчёт:
`audit-report-independent.md` (581 строка). Этот файл — аудит автора и независимую
проверку не заменяет; он оставлен как есть, чтобы было видно, что именно автор
считал проверенным до стороннего взгляда.

Что аудитор воспроизвёл самостоятельно и что совпало: `4 failed, 8 passed` на
оригинале с теми же именами тестов, `12 passed` на исправленной версии, убийство
мутантов M1/M2/M3 при выживании трёх собственных тестов пакета, подлинность
оригинала по SHA-256.

Что аудитор опроверг (подтверждено мной вручную):

1. **Формулировка D1 была ложной.** Тип `FIXED_POINT_HOLD` был достижим через
   `classify(0.5, 0.9, 0.9, 1)` и в оригинале; недостижим он был только через
   `analyze()`. Утверждение «нельзя получить ни на одном входе» отозвано.
2. **Первая правка D1 дала регрессию и откачена.** На `min_lag=1` чистый синус с
   периодом 40 классифицировался как `FIXED_POINT_HOLD`; на `min_lag=2` —
   `PERIODIC_LOOP`.
3. **Правка D1 не была покрыта ни одним тестом:** мутант `min_lag=1 → 2` проходил
   все 12 тестов. Теперь закрыта.
4. **Исправление D3 неполно:** при константном локальном окне `kerg = 0.5` под
   статусом `SIMULATED`. Не исправлено, требует решения.
5. **Оговорка про рампу была прозой:** рампа канонизируется (`PERIODIC_LOOP`).

Дополнительно исправлены найденные аудитом дефекты: падение на нечисловом входе и
на нулевой частоте, `nan` в `kerg` при переполнении. Тестов стало **17/17 зелёных**,
мутантов убито семь.

**Чего этот аудит НЕ проверил** (честные границы): калибровку порогов — датасета
калибровки нет; соответствие пакета внешнему канону за пределами архива; ряды
длиннее 8000 точек; валидацию по JSON Schema библиотекой (`jsonschema` не
установлен).
