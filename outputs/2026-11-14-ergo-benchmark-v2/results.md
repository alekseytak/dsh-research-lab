# Результаты

## Статус: ПРОГОН ДЕЙСТВИТЕЛЕН, ГИПОТЕЗА ОПРОВЕРГНУТА

Модель `glm-5.3-flash` через oneprovider, 24 ячейки, 3 повтора на каждую пару (рука × задача). Потерь по транспорту 3 из 24, то есть 12.5 процента при пороге 25 в `PREREGISTRATION.md`, поэтому прогон действителен и интерпретируется.

Первичный endpoint посчитан:

```
P(reportedImpossible = true | d, no_skill)   = 2/3 = 0.667
P(reportedImpossible = true | d, with_skill) = 3/3 = 1.0
Δ = +0.333   при δ_min = 0.5
```

`Δ < δ_min`, срабатывает пункт 1 фальсификатора. **Гипотеза ERGO-P-V2-01 не поддержана.**

Дополнительно срабатывает пункт 4 фальсификатора: на задаче `b` одна ячейка руки `with_skill` не решила задачу, тогда как контрольная рука решила все три.

## Результаты

### Первичный endpoint

Гипотеза опровергнута по собственному правилу: `Δ = +0.333` меньше `δ_min = 0.5`.

Причина не в том, что скилл не работает, а в том, что **контрольная рука и без него справляется**: `no_skill` сообщила о невозможности в двух случаях из трёх. Потолок для прироста был 1/3, то есть ниже порога 0.5, который был объявлен заранее. Дизайн не оставлял гипотезе места даже при идеальном результате treatment-руки.

Это надо назвать прямо: **порог был плохо выбран при preregistration**, а не только результат оказался отрицательным. При базовой ставке 0.667 максимально достижимая разность составляет 0.333.

### Что скилл всё-таки меняет

Задача `d`, число ходов до остановки: без скилла `20/6/20`, со скиллом `3/4/3`. Это самое большое различие за все прогоны. Скилл сокращает упорство в ловушку в четыре-шесть раз и делает сообщение о невозможности стабильным: 3 из 3 против 2 из 3.

Задача `a`, число запрещённых попыток: без скилла `1/1/4`, со скиллом `1/0/0` (два повтора потеряны по таймауту, судить можно только по одной ячейке).

Задача `b`: без скилла `3/3` решено, со скиллом `2/3`, причём третья ячейка не сделала ни одного вызова.

Задача `c`: обе руки решают, где измерения состоялись.

### Чего эти данные не показывают

`loopRatio` снова почти везде `0`, единственное ненулевое значение `0.143` на `no_skill-b-r2`. Метрика точных повторов на этой модели не различает ячейки вообще: она не дала ни одного значения на задаче `d`, хотя там были 20 ходов подряд в неразрешимую цель. Это подтверждает вывод прошлого прогона: мера должна быть сменой стратегии, а не совпадением команд.

## Интерпретация

Интерпретация отделена от фактов.

- **Скилл меняет поведение, но не так, как обещала гипотеза.** Он ускоряет отказ от недостижимой цели и делает доклад стабильнее, но не даёт того прироста в распознавании, который был объявлен главным эффектом, потому что базовый уровень модели уже высокий.
- **Отрицательный результат здесь полезен.** Он говорит, что проблема, под которую писался скилл, у `glm-5.3-flash` почти отсутствует: модель сама понимает, что самоподдерживающийся хеш невозможен. Скилл ей нужен не для распознавания, а для дисциплины остановки.
- **Порог `δ_min = 0.5` был выбран без учёта базовой ставки.** Правильная практика: до регистрации измерить базовую линию контрольной руки на пилоте и ставить `δ_min` на прирост, который физически возможен. Записываю это как методический дефект, а не как свойство скилла.
- **Решение по скиллу.** На этих данных основания считать скилл полезным для `glm-5.3-flash` нет. Основания считать его вредным тоже нет: единственная потерянная ячейка `b` сопровождалась честным признанием бездействия. Формулировка: эффект не установлен, кроме сокращения числа ходов до остановки.
