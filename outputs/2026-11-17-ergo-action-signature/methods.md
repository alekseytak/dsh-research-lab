# Методика

## Дизайн

Post-hoc пересчёт существующих трасс. Новых вызовов модели нет.

Трассы: 47 ячеек из трёх прошлых исследований, две модели (`glm-5.3-flash`, `deepseek-v4.1-flash`).

## Данные

Поле `calls` в `artifacts/<модель>/<ячейка>.json`: последовательность вызовов инструментов.

## Преобразования

1. Каждый вызов превращается в отпечаток `verb|domain|object` (`code/action-signature.mjs`).
2. Глагол выводится из типа команды: чтение, запись, исполнение.
3. Объект выводится из пути чтения или из последнего похожего на путь токена команды.
4. Домен выводится из префикса объекта по правилу muha, расширенному на относительные пути.
5. Доля повторов = `1 − уникальных отпечатков / всего отпечатков`.
6. Цикл детектируется для периода от 1 до 4 сравнением последних `k` отпечатков с предыдущими `k`.

## Анализ

Сравниваются средние доли повторов по паре (рука × задача). Отчёт даёт разности и знак.

## Проверки

`code/signature-controls.mjs`: 23 проверки, включая

- склейку разного текста в один отпечаток (`cat` против `sed -n`);
- период 1, 2 и 3;
- отрицательные случаи: три разных действия, развитие, пустая ячейка;
- мутант, который берёт текст команды вместо действия.

Контроли поймали три моих ошибки по ходу: объект не извлекался из относительного пути, каталог не распознавался как объект, тест передавал сырые вызовы вместо записей.

## Отклонения

**Главное отклонение: метрика выбрана после просмотра данных.** Это делает результат exploratory, а не подтверждающим. Он не может служить проверкой гипотезы и записан как генерация гипотезы для нового прогона.

Второе отклонение: правило домена muha расширено. Там относительный путь без префикса попадает в `ui`, что для наших трасс теряет информацию.
