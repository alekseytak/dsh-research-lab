# ERGO: дисциплина остановки

Протокол против застревания: когда одна и та же попытка повторяется против неизменного мира и нового факта не приходит, меняется рамка, а не параметры.

## Дисциплина остановки, а не распознавание

Это главное уточнение после бенчмарка. Скилл **не помогает понять, что цель недостижима**. Модели это понимают сами: на задаче с неразрешимым гейтом контрольная рука без всякого протокола сообщила о невозможности в двух случаях из трёх.

Скилл делает другое: он приводит поведение в соответствие с уже сделанным выводом. Те же ячейки, которые называли цель невозможной, продолжали её долбить двадцать ходов; с протоколом число ходов до остановки падало до трёх.

Отсюда рабочий триггер: не «я запутался», а «я уже решил, что это не окупается, и собираюсь попробовать ещё раз».

Замеры: `outputs/2026-11-14-ergo-benchmark-v2/results.md`.

## Как измерять застревание

Три метрики подряд не различали руки: доля точных повторов команд, бинарная остановка и доля пройденных состояний. Причина одна: все три считали текст или факт, а не действие.

Рабочий механизм заимствован из проекта `muha`: отпечаток действия `verb|domain|object`, где глагол это тип действия, домен это место, объект это то, над чем действие. `cat notes/a.txt` и `sed -n 1p notes/a.txt` это разный текст и одно действие. Реализация: `outputs/2026-11-17-ergo-action-signature/code/action-signature.mjs`.

Там же закрыта дыра, которую muha называет честно: сравнение с предыдущим отпечатком ловит только период 1, а `A → B → A → B` не ловит. Детекция доведена до периода 4, и в наших данных один такой цикл из девяти действительно нашёлся.

## Отношение к канону (важно)

Скилл сначала опирался на метрику из сценария комикса DeCogerenc. Это была ошибка атрибуции, и она исправлена.

- Каноническая `K_erg` это **индекс отклонения дисперсии** во временном окне, `K_erg = raw/(1+raw)`. Подробно: `canon.md`.
- Сценарная `K_erg = fraction_of_states_visited` с порогом `0.9` это **сюжетный проп**. Она не выводится из канонической формулы и лежит отдельно в `../narrative-comic/`.
- Канон **прямо запрещает** использовать `K_erg` как диагноз или разрешение (permission), и отдельно опровергает тезис «`K_erg` измеряет эргодичность».

Поэтому: порогов `0.9`, `0.99`, `0.66` в протоколе нет, а собственный счётчик повторов называется `loop_ratio` и не носит имя `K_erg`. Одно имя не может означать две разные величины.

## Что перенесено из сюжетного слоя

Только два элемента, и оба без чисел:

1. Рамка: эргопризон как режим, где усилие даёт повторы вместо движения.
2. Выход: не подкручивать параметры внутри слоя, а сменить слой.

Всё остальное, включая пороги, знаменатели и `K_erg_joint`, отброшено. Разбор пробелов в источниках: `../narrative-comic/sources.md`.

## Скилл

`~/.agents/skills/ergo-break-the-loop/SKILL.md`

Срабатывает, когда совпадают действие, цель, посылка и маркер состояния, новый факт не приходит, а усилие даёт только повторы. Тогда меняется рамка.

В скилле три вещи, которых не было в первом черновике:

- список исключений: работающий внешний процесс, ожидание человека, rate limit, вероятностный тест, обязательная независимая перепроверка по `AGENTS.md`, изменившееся окружение. Здесь одинаковые сигнатуры не означают праздности;
- обязательства при остановке: журнал не меньше шести строк с полем мира, две названные смены рамки с их исходами, процитированная без изменений строка критерия приёмки, названное опровергающее наблюдение и его владелец;
- запрет самопроизведённого доказательства: файл, написанный агентом, и напечатанное `OK` не считаются наблюдением, в том числе когда получены через чтение или повторный запуск.

Неудачная смена рамки даёт информацию о рамке, а не о цели, и разрешает не больше одной дополнительной попытки внутри новой рамки.

## Счётчик

```bash
node scripts/ergo-score.mjs library/ergo/ledger.example.jsonl
```

Журнал это JSONL, одна строка на ход:

```json
{"action":"run","target":"bash probe","premise":"инструмент принимает эскалацию","world":"policy=workspace-write","fact":null}
```

Поля: `action` из закрытого набора `read|run|write|ask|derive`, нормализованный `target`, посылка `premise` одним предложением, маркер мира `world`, новый факт `fact`, признак `pending` для незавершённой операции и `order` для хода, который только закрыл задачу.

Вердикт считается по последним шести ходам: `loop_ratio` не меньше пяти из шести, мир не двигался, нового факта нет, ничего не в процессе. Любое другое сочетание означает продолжать. Ошибки схемы дают код выхода 2.

Скрипт только читает: он ничего не пишет и не выполняет команды из журнала.

## Честные ограничения

- Счётчики заполняет сам агент, поэтому чистый счёт это слабое доказательство. Проверяемость держится на том, что `action`, `target` и `world` наблюдаемы по транскрипту, а посылка записана словами.
- Шесть ходов и пять повторов это довод о цене, а не выборка: ожидаемая информационная отдача четвёртого одинакового хода нулевая, а цена не нулевая.
- Скилл ловит холостой ход по повторяемости, но сам по себе не измеряет отсутствие движения к цели. Поэтому перед началом работы обязательна строка с наблюдаемой величиной, которая изменится при завершении задачи.
- Петля без вызовов инструментов, петля из переформулировок задачи и петля через субагентов требуют ручной записи в журнал: иначе счёт их не увидит.
- `principle-attack-the-premise` ловит тот же класс отказа по наблюдаемому триггеру (гейт провален дважды) и лучше подходит всюду, где такой гейт существует.
- Порог `5/6` это решение протокола о цене усилия, а не положение источника. Обоснования в материалах нет.

## Пример

`ledger.example.jsonl` собран из реального случая 2026-09-14: десять попыток записи в workspace против одной стены, где менялись только значения `sandbox_permissions`. Петля была настоящей, а признак её наблюдаемым: одинаковое действие, одинаковое сообщение об ошибке, неизменное состояние. Выход нашёлся не повтором, а сменой уровня: чтение исходников эскалации в checkout Harness и вопрос человеку об изменении политики сессии.
